这是一份为你整理的 **npm 网络配置（镜像与代理）学习笔记**。当遇到 npm 安装缓慢、卡住不动或报错时，可以随时查阅这篇笔记来排查和解决问题。

------

# 📖 npm 网络配置与加速学习笔记

在遇到 npm 安装包（如 `claude-code`）速度极慢或卡死时，通常是因为网络连通性问题。解决这个问题有两个主要方向：**换用国内镜像源** 或 **让 npm 走本地代理软件**。

## 🔍 第一步：查看当前网络配置

在动手修改之前，先确认 npm 当前的状态。打开终端，输入以下命令：

Bash

```
# 查看当前正在使用的源（默认是 https://registry.npmjs.org/）
npm config get registry

# 查看当前的 HTTP 代理设置（默认是 null）
npm config get proxy

# 查看当前的 HTTPS 代理设置（默认是 null）
npm config get https-proxy
```

如果你的输出是官方源且代理为 `null`，说明你在**直连海外服务器**，这也是下载慢的根本原因。

------

## 🚀 方案一：使用国内镜像源（推荐，最省事）

通过将下载服务器替换为国内的镜像节点（如淘宝 npm 镜像），可以大幅提升下载速度。此方案**不需要**开启任何代理软件。

## 1. 临时使用（仅生效一次）

如果你不想改变全局配置，可以在安装命令后加上 `--registry` 参数：

Bash

```
npm install -g <包名> --registry=https://registry.npmmirror.com
```

## 2. 永久配置（一劳永逸）

如果你经常使用 npm，建议直接将国内镜像设置为默认源：

Bash

```
# 设置淘宝/国内镜像源
npm config set registry https://registry.npmmirror.com/

# 验证是否设置成功
npm config get registry
```

## 3. 恢复官方源（如果需要）

如果某些特定的包在镜像站上找不到或版本没更新，可以随时切回官方源：

Bash

```
npm config set registry https://registry.npmjs.org/
```

------

## 🌍 方案二：配置本地代理（适合开启了代理软件的用户）

如果你习惯挂着本地代理软件（如 Clash、V2Ray 等），并且希望 npm 的流量直接走代理节点下载原汁原味的官方包，可以进行代理配置。

## 1. 确认本地代理端口

查看你的代理软件设置，找到“本地监听端口”（Local Port）。

- 常见代理软件端口：`7890`（Clash系）、`10808`（V2Ray系）等。
- 本地 IP 通常固定为 `127.0.0.1`。

## 2. 设置 npm 代理

假设你的代理地址是 `http://127.0.0.1:7890`，在终端执行：

Bash

```
# 配置 HTTP 和 HTTPS 代理
npm config set proxy http://127.0.0.1:7890
npm config set https-proxy http://127.0.0.1:7890
```

*(注：即使是 https-proxy，后面的地址一般也填 `http://...`，因为本地代理客户端通常通过 HTTP 协议接收转发请求。)*

## 3. 取消代理设置（⚠️ 关键坑点）

**注意：** 如果你关闭了代理软件，npm 仍然会傻傻地把请求发给这个已经关闭的端口，导致所有安装报错（如 `ECONNREFUSED`）。因此，不用代理时务必清除配置：

Bash

```
npm config rm proxy
npm config rm https-proxy
```

------

## 🛠️ 终极排错技巧：开启详细日志（Verbose 模式）

npm 默认会隐藏安装过程中的底层网络请求。如果你觉得它“卡死了”，可以在任何安装命令后加上日志参数，让它把每一步都打印出来：

- **命令后缀**：`-dd` 或 `--verbose`

- **使用示例**：

  Bash

  ```
  npm install -g @anthropic-ai/claude-code@latest -dd
  ```

- **如何看日志**：敲下回车后盯着滚动的终端，如果看到不断有 `http fetch GET 200` 并跟随着镜像源或代理的 URL，就说明配置已经生效，网络正在高速下载中。

------

**💡 总结建议**：

日常开发中，**方案一（配置镜像源）** 是最稳定、干扰最少的选择；只有在镜像源出问题，或者你必须强制拉取某些最新的海外依赖时，才建议使用 **方案二（走代理）**。
