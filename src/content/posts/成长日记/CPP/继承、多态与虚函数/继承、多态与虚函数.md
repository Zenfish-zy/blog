## C++ 继承、多态与虚函数底层原理学习笔记

### 1. 核心问题：为什么需要虚函数？

在 C++ 中，当使用**父类指针（或引用）\**指向\**子类对象**时，如果函数不是虚函数，编译器会采用**静态绑定**；如果是虚函数，则采用**动态绑定**。虚函数是实现运行期多态的唯一途径。

| **特性**     | **普通成员函数 (静态绑定)**    | **虚函数 virtual (动态绑定)**        |
| ------------ | ------------------------------ | ------------------------------------ |
| **判定时机** | 编译期决定                     | 运行期决定                           |
| **调用依据** | 根据**指针本身的类型**调用     | 根据**指针实际指向的对象类型**调用   |
| **适用场景** | 明确不需要被子类修改的基础功能 | 需要子类重写并展现不同行为的多态功能 |

------

### 2. 架构思考：为什么要用父类指针操作子类对象？

初学者常问：“既然是一只狗，为什么不用 `Dog*`，非要套上 `Animal*` 的马甲？”

答案是为了应对复杂软件开发中的**通用性与解耦**。

- **统一管理异构集合：** 可以将 `Dog`、`Cat`、`Cow` 等不同类型的对象指针，统一塞进同一个 `std::vector<Animal*>` 容器中进行批量操作（如遍历调用叫声函数）。
- **编写通用接口：** 函数参数只需定义为 `void feed(Animal* a)`，即可接收任何继承自 `Animal` 的子类对象，调用者无需为每种动物编写重载函数。
- **极致的扩展性（开闭原则）：** 未来增加新动物（如 `Dinosaur`）时，只需继承 `Animal` 并重写虚函数，**无需修改**原有的业务逻辑代码即可完美融合。

------

### 3. 底层揭秘：虚函数是如何工作的？

虚函数的魔法依赖于两个隐藏机制：**一张表**与**一个指针**。

- **虚函数表 (V-Table - Virtual Table)：** * 属于**类级别**。只要类中声明了虚函数，编译器就会在编译期为该类生成一张表，本质是一个函数指针数组，记录了该类所有虚函数的真实内存地址。
  - 如果子类重写了父类的虚函数，子类 V-Table 中对应的函数地址会被**覆盖/替换**为子类自己的函数地址。
- **虚表指针 (vptr - Virtual Pointer)：** * 属于**对象级别**。当包含虚函数的类实例化成对象时，编译器会在该对象的内存空间中（通常是最开头）隐式安插一个指针 `vptr`。
  - `vptr` 的唯一作用就是**指向该对象所属类的 V-Table**。

**调用流程（按图索骥）：**

当执行 `animalPtr->speak()` 时，程序顺着指针找到实际对象 -> 读取对象头部的 `vptr` -> 根据 `vptr` 找到对应的 V-Table -> 在表中查出 `speak` 函数的真实地址 -> 跳转执行。

------

### 4. 核心顿悟：父类指针如何在子类对象中准确寻址？

**误区：** 认为子类对象会随意改变父类属性的排列顺序或内存格式，导致父类指针找不到对应的数据。

**真相（C++ 内存布局铁律）：** 子类的内存布局 = **原封不动的父类内存布局** + **子类新增的成员属性**。并且，**父类的内存永远排在最前面！**

- **指针是“盲目”的：** 当 `Animal* a = new Dog();` 时，指针 `a` 认为自己指向的就是一个普通的 `Animal`。它按照 `Animal` 的内存排版去计算偏移量。
- **严丝合缝的布局：** 因为 `Dog` 乖乖地把 `Animal` 的所有属性（包括隐藏的 `vptr`）原封不动地放在了自己内存的最前面，所以指针 `a` 去读取第一个元素（`vptr`）或父类属性时，拿到的绝对是正确位置的数据。
- **狸猫换太子：** 虽然指针 `a` 按照父类的规矩摸到了对象头部的 `vptr`，但 `Dog` 在构造时，早就把这个 `vptr` 的指向**掉包**成了 `Dog` 类的 V-Table。因此，指针 `a` 顺藤摸瓜查表时，查到的自然就是 `Dog` 重写后的函数地址了。

> **生动比喻：**
>
> 父类指针就像去写字楼 101 找“王经理”（调用虚函数）。它不知道这家公司已经被收购换名字了（子类对象），它只是按老规矩敲门问前台（读取 `vptr`）。前台把它带去查通讯录（V-Table），最终见到的其实是新公司的新任“王经理”（子类重写的函数）。
