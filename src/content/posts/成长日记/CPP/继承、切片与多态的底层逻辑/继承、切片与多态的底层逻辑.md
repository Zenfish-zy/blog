# C++ 核心进阶笔记：继承、切片与多态的底层逻辑

## 一、 继承体系中的生命周期（构造与析构）

**核心比喻：“盖楼与拆楼”**

基类（Base）是地基和承重墙，派生类（Derived）是精装修和扩展阳台。

### 1. 构造与析构的顺序

- **诞生（构造，由内而外）**：`基类构造函数` -> `派生类成员构造` -> `派生类构造函数体`。
  - *原因*：派生类的初始化可能依赖基类的数据，必须先打好地基。
- **死亡（析构，由外而内）**：`派生类析构函数` -> `派生类成员析构` -> `基类析构函数`。
  - *原因*：派生类在清理资源时可能用到基类的方法，必须先拆精装修，最后挖地基。
- **克隆（拷贝与赋值）**：派生类有责任在自己的拷贝构造/赋值运算符中，**显式调用**基类的对应函数（如 `Base(other)` 或 `Base::operator=(other)`），否则基类部分的数据不会被正确复制。

### 2. 知识点补充：右值与 `override` 关键字

- **常量引用绑定右值**：`const std::string&` 可以接收 `"Default Derived"` 这样的字符串字面量。编译器会在底层隐式创建一个没有名字的 `std::string` 临时对象（右值），并延长其生命周期供函数使用。
- **`override` 关键字**：它是给编译器看的“防呆标签”。加上它，编译器会严格检查基类中是否存在签名完全一致的虚函数供你重写。如果拼写错误或漏写 `const`，编译器会直接报错，避免产生难以排查的“隐藏（Hiding）”Bug。

### 3. 代码示例：生命周期全景



```C++
#include <iostream>
#include <string>

class Base {
public:
    Base(const std::string& name) { std::cout << "Base 构造: " << name << "\n"; }
    virtual ~Base() { std::cout << "Base 析构\n"; } // 黄金法则：基类析构必为虚函数
};

class Derived : public Base {
public:
    // 派生类必须在初始化列表中负责基类的构造
    Derived(const std::string& name) : Base(name) { std::cout << "Derived 构造\n"; }
    ~Derived() override { std::cout << "Derived 析构\n"; } // override 确保正确重写
};

int main() {
    Derived d("Test"); 
    // 输出顺序: 
    // Base 构造: Test
    // Derived 构造
    // Derived 析构
    // Base 析构
    return 0;
}
```

## 二、 容器与对象切片（Object Slicing）

**核心概念：C++ 的值语义与多态天生不合。**

多态只能通过**指针或引用**触发。如果将派生类对象按“值”存入基类容器，就会发生可怕的“切片”。

### 1. 切片的两个物理维度

- **物理肉体切片（丢失派生类数据）**：

  容器 `std::vector<Base> vec;` 的每个格子大小被焊死为 `sizeof(Base)`。当尝试塞入 `Derived` 对象时，基类拷贝构造函数只认得基类的成员变量。`Derived` 新增的成员因为“装不下”且“不认识”，被直接物理丢弃。

- **逻辑灵魂切片（丢失多态性）**：

  即使 `Derived` 没有增加任何新变量（大小与基类相同），多态依然会失效。因为放入容器的本质是**调用 `Base` 的拷贝构造函数重新建立一个全新的对象**。只要是建 `Base` 对象，编译器就会强制将这个新对象的 `vptr`（虚表指针）重新指向 `Base` 的虚函数表。

### 2. 切片 vs 多态 代码对比



```C++
#include <iostream>
#include <vector>
#include <memory>

class Base {
public:
    virtual void show() const { std::cout << "Base\n"; }
};

class Derived : public Base {
public:
    int extra_data = 100; // 派生类新增属性
    void show() const override { std::cout << "Derived\n"; }
};

int main() {
    Derived d;

    // 灾难现场：发生切片
    std::vector<Base> vecValue;
    vecValue.push_back(d); 
    vecValue[0].show(); // 输出: Base (灵魂被重置，肉体 extra_data 被丢弃)

    // 正确做法：使用智能指针
    std::vector<std::unique_ptr<Base>> vecPtr;
    vecPtr.push_back(std::make_unique<Derived>());
    vecPtr[0]->show(); // 输出: Derived (存的是地址，原本的对象在堆中完好无损)
    
    return 0;
}
```

## 三、 终极揭秘：虚函数底层的内存布局

**核心定律：多态依赖于“一张只读的表”和“一个可写的指针”。**

### 1. 虚函数表（V-Table）：墙上的只读索引牌

- **归属**：属于整个**类（Class）**，不属于某个对象。
- **位置**：被编译器刻死在内存的**常量区（通常是 `.rodata` 只读数据段）**。绝对不可修改，防止黑客进行“虚表劫持”攻击。
- **内容**：存放着该类所有虚函数的真实内存地址（函数指针数组）。

### 2. 虚表指针（vptr）：对象自带的指南针

- **归属**：属于每一个实例化的**对象（Object）**。
- **位置**：通常位于对象内存布局的**最开头**（占用 8 个字节，64位系统）。因为对象存在于栈区或堆区，所以 `vptr` 是**可读可写的**。
- **它的值从哪来**：在对象的**构造函数**执行时，编译器会偷偷插入代码：`this->vptr = &本类的虚函数表地址;`。

### 3. 多态的汇编级运转流程

当你执行 `basePtr->show();` 时（假设 `basePtr` 实际指向 `Derived` 对象）：

1. **寻址**：CPU 顺着指针找到堆/栈中的对象。
2. **取针**：读取对象头部的前 8 个字节，拿到 `vptr`（此时它指向 `Derived` 的虚表）。
3. **查表**：顺着 `vptr` 找到常量区中的 `Derived_VTable`，取出对应索引的函数地址。
4. **跳转**：执行底层的 `call` 指令跳转到真正的函数执行。

### 4. 再次呼应切片（伪代码模拟编译器行为）

当 `Base` 拷贝构造函数被调用以生成切片对象时，底层发生了什么：

    // 1. 灵魂注入：无视 other 的 vptr，强行修改新对象头部的指南针
