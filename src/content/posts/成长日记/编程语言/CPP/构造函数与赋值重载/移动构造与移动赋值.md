# 📝 C++ 移动语义与资源管理学习笔记

## 1. 移动构造函数与 `noexcept`

在定义移动构造函数和移动赋值运算符时，几乎总是应该加上 `noexcept` 关键字。

- **核心作用**：向编译器保证该函数**绝对不会抛出异常**。
- **性能影响（以 `std::vector` 为例）**：
  - 当 `std::vector` 扩容（Reallocation）时，需要把旧元素转移到新内存。
  - **有 `noexcept`**：容器确信移动是安全的，会高效地调用**移动构造函数**。
  - **无 `noexcept`**：为了保证强异常安全（防止移动一半报错导致数据损坏），容器会退化使用昂贵的**拷贝构造函数**进行深拷贝，导致移动语义的性能优势完全丢失。

## 2. `std::move` 的真面目

`std::move` 的名字具有欺骗性，它在底层**不移动任何数据**，也不产生任何可执行代码。

- **本质**：它仅仅是一个**无条件的类型转换（Cast）**，相当于 `static_cast<T&&>`。
- **作用**：将一个**左值**（有名字、通常不能被安全夺取资源的对象）强行转换为**右值引用**（`&&`）。
- **为什么需要它**：编译器默认不会去“偷”左值的资源（太危险）。只有程序员显式调用 `std::move()`，相当于赋予了编译器“掏空这个对象”的许可。
- **掏空动作**：真正的“移动（偷）”操作是由**移动构造/赋值函数**内部的代码完成的（例如接管指针后，将原对象的指针置为 `nullptr`）。

## 3. 拷贝赋值 vs 移动赋值：重载决议的艺术

在 C++ 中，`a = b;` 本质上是函数调用 `a.operator=(b);`。移动赋值并没有什么魔法，它完完全全就是拷贝赋值的**函数重载**。

编译器通过判断等号右边对象的**值类别**来决定调用哪个重载：

- **左值（Lvalue）**：有名字、后续还要使用的对象。
  - **匹配**：`operator=(const T&)`
  - **行为**：**拷贝赋值**（深拷贝，因为不能破坏原对象）。
- **右值（Rvalue）**：临时对象（如 `T(10)`）或被 `std::move()` 转换的对象。
  - **匹配**：`operator=(T&&)`
  - **行为**：**移动赋值**（直接接管资源，因为原对象马上就要消亡或被废弃）。

## 4. 移动与拷贝中的必修课：自赋值检查

无论是拷贝赋值还是移动赋值，函数开头都必须包含自赋值检查：

C++

```
if (this == &other) {
    return *this;
}
```

- **防御目的**：防止对象“自杀”。
- **如果不写**：当发生 `obj = obj;` 或 `obj = std::move(obj);` 时，程序会首先 `delete[] data_;` 清理自身的旧内存。随后再去读取 `other.data_` 时，由于 `other` 就是 `this`，数据已经被自己销毁，会导致悬挂指针（Dangling Pointer）甚至程序直接崩溃。

## 5. 资源管理的“两步走”战略

在编写移动语义函数处理动态资源（如指针、堆内存）时，必须严格执行两步：

1. **接管**：`data_ = other.data_;` （把对方的资源据为己有）。
2. **斩断**：`other.data_ = nullptr;` （把对方掏空，防止对方在析构时把我们刚抢来的资源给释放掉，造成 Double Free 错误）。
